# 市场资讯刷新失败修复验收

## 行为

- 官方资讯请求继续优先使用 Electron 的系统网络连接；连接或响应正文读取失败后，使用 Node 网络连接再尝试一次。每次尝试的超时均为 12 秒，保留请求方法、请求头和 POST 参数。HTTP 错误、JSON 格式错误和调用者主动取消不会触发备用连接。
- 多只股票遇到相同来源错误时，界面按来源与原因合并显示一次，使用中文来源名和“请求超时”等说明。
- 来源刷新部分成功时，更新成功来源，保留失败来源已有的缓存；全部来源失败时，不覆盖磁盘缓存。
- 失败后约 5 分钟重试，按每分钟的调度节拍触发。普通自选股只有在来源全部成功后才记为当日已查询；成功后仍按原来的收盘后每日一次规则运行。重点股票正常刷新间隔仍为 15 分钟。
- 定时刷新批次不重叠；每只股票分别保存刷新状态，其他股票成功不会抹掉尚未恢复的错误。

## 自动校验

- TypeScript：`tsc --noEmit`。
- ESLint：检查 `main/news/`、`main/service.ts`、`main/service.test.ts` 和 `shared/constants.ts`。
- Vitest：`vitest run src/modules/market-insight`，覆盖网络回退、HTTP/JSON/取消边界、缓存合并、并发状态隔离、七只股票错误去重、失败重试和调度互斥。
- 只做静态检查与无界面的来源请求验证，不启动应用界面，不执行 `build:unpacked`。

2026-10-25 无界面来源验证：模拟 Chromium 连接超时，再执行实际 Provider 的 Node 备用连接，取得新希望公司公告 30 条、近 7 天证监会要闻 7 条、上交所通知 15 条、深交所通知 6 条。北交所该次请求进入重定向循环，提示“来源重定向异常”；其他来源照常返回。以上数量和可达性仅代表验证时结果。

## 人工验收

1. 打开一只自选股的“市场资讯”，执行刷新，检查要闻、公司公告和交易所通知能否返回。
2. 在多只股票同时刷新失败时，检查提示是否只列一次各来源，没有按股票重复的英文超时长串。
3. 已有资讯时断网刷新，检查旧内容保留；恢复网络后手动刷新，或等待约 5–6 分钟，检查资讯恢复及错误提示消失。
4. 某个来源单独不可用时，检查其他来源仍可更新，失败来源已有内容仍保留。来源返回 HTTP 错误时应如实提示该错误。
5. 交易日收盘后，普通自选股第一次刷新失败再恢复，检查当天仍会重试；成功后不再每分钟重复查询。
