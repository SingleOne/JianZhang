# 持仓止损线验收

当前版本按每只股票的汇总持仓维护一条规则。设置入口是自选表的股价提醒按钮：点击「添加条件」，在条件选择框中选择「止损线」，其后直接显示模式、止损比例和重设基准按钮。已有止损配置显示为条件行；删除该条件或切换为其他指标后保存，即关闭止损线。同一股票仅可添加一条止损线。已启用的股票在名称旁显示止损价，点击可重新设置。

## 计算与存储

- `trailingClose`：以有效行情中的 `previousClose` 初始化及上调基准，保留已记录的最高值。
- `fixedCost`：锁定设置时的汇总成本，之后加减仓不自动改变基准。
- `WatchStock.stopLoss` 的存在表示启用，不保存 `enabled: false` 或空规则。字段只有模式、比例、基准价、重设标识，以及移动模式最近处理的行情日期。
- 当前止损价、距离、触线状态、最新行情和历史价格列表均不写入规则。
- 同一规则正常更新只上移。重设基准会产生新标识，允许主动降低基准；仅修改比例会保留此前最高基准。保存旧编辑草稿不会覆盖后台已经抬高的同一基准。
- 关闭、清仓、导入无持仓配置时删除规则。重新建仓需重新启用。
- 核心配置、完整备份和 Gist 共用已有导出路径，因此一并保存高点；恢复后直接沿用，不回补停用期间的历史高点。缓存清理不会影响规则。
- `quoteDate` 指提供昨收的行情所属交易日，不表示历史连续覆盖日期，也不是高点收盘日。

使用最终字段（包括防止旧草稿覆盖基准的随机重设标识）模拟 100 条规则，紧凑 JSON 约 14.5 KiB，gzip 加 Base64 约 4.0 KiB；1,000 条约 145.6 KiB / 38.5 KiB。数值是止损数据独立序列化的模拟测量，不含完整备份及加密外壳。未启用股票没有新增字段，且不累积历史记录。

## 订阅接入

纯计算入口为 `src/shared/stop-loss.ts` 的 `evaluateStopLoss` / `evaluateStopLosses`。跨窗口接入可使用 `stockApi.getStopLossSnapshots()`、`stockApi.onStopLossUpdated(callback)`；`src/lib/stop-loss.ts` 的 `subscribeStopLoss` 会先订阅再读取初始结果，并返回取消订阅函数。

返回 `stopPrice`、`referencePrice`、`distancePercent`、`reached`、`dataState` 和 `dataAt`。价格低于或等于止损价时 `reached=true`；比较所需行情无效、过期或时间未知时为 `null`。非交易时段的有效报价可以用于历史快照比较，并带有 `closed` 状态。距离为 `(最新价 - 止损价) / 最新价 × 100%`，跌破后为负数。

订阅广播提供当前完整结果列表，关闭规则后对应股票从列表消失。订阅方自行处理触线、恢复、通知去重或业务动作；止损模块不发送系统通知或创建交易。

## 用户界面验收

1. 无持仓股票打开股价提醒，不应出现止损设置；原有价格提醒继续可用。
2. 有持仓股票点击「添加条件」，选择「止损线」，确认模式和比例输入框紧随其后，默认移动模式预览基于昨收；保存后名称旁出现止损价。重新打开应显示已有止损条件，其他条件不可重复选择止损线。
3. 在分时图工具栏切换「止损线」，确认虚线和轴价格标签随之显示/隐藏，切换不重建规则。开关按本机保存，重新打开详情仍沿用选择。
4. 换日后刷新：昨收创新高时抬线，昨收降低时保留基准；盘中最新价变化不抬线。同一行情重复刷新不重复保存规则。
5. 最新价恰好等于止损价时显示已触线。缺少有效行情时显示等待有效行情，避免误报未触线。
6. 成本模式启用后变更持仓成本，确认锁定基准不变；点击「重设基准」后预览新值，保存生效。
7. 删除止损条件或将其切换为其他指标并保存，导出配置中该股票不包含 `stopLoss`；点击取消则保留原配置。清仓后同样移除；重新建仓后保持未启用。
8. 将含规则的配置备份到 Gist，在另一台设备手动覆盖恢复，确认高点、模式及比例保留。用较低的昨收刷新后高点不降低。
9. 打开设置后让后台抬高基准，再修改比例并保存，确认同一规则高点不会被旧草稿降低。主动重设时允许使用新基准。

拆股、除权或行情价格口径变化后，可在设置中重设基准并预览价格；本功能不自动换算旧基准。
