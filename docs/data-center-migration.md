# 组件数据中心迁移

目标：主进程维护权威数据，每个渲染窗口提供共享快照与按范围订阅。组件读取中心数据，提交明确修改命令，仅在本地保留交互状态和编辑草稿。

## 第 1 步的边界

- `src/lib/data-center/store.ts` 提供快照和选择器订阅。同一次发布先提交快照，再通知选择结果改变的订阅者；选择结果不变时保留引用。
- `center.ts` 统一接收现有状态和行情事件，复用 `state-client.ts` 的 revision 与增量 IPC 逻辑。中心复用已有状态对象，不进行整份深拷贝。
- `src/lib/api.ts` 导出窗口级 `dataCenter`；原 `stockApi` 改为兼容门面。旧组件可逐步迁移，不额外注册底层状态、行情事件监听。
- `hooks.ts` 通过 `useSyncExternalStore` 提供 `useAppData`、`useStockQuote` 和 `useAppSetting`。快照按只读使用；对象或数组派生结果需使用稳定选择器和适当的相等判断。
- `TaskbarTicker` 是首个接入组件，当时移除了本地 `state`、`quotes` 副本但仍订阅完整集合；第 6 步已改为辅助窗口字段及可见股票行情订阅。
- 初始化与手动刷新期间若收到行情推送，中心保留推送快照。定向刷新返回的部分数据合并到中心，兼容门面仍返回原请求结果。

## 第 2 步的边界

- App 已移除行情数组、本地行情合并、行情订阅和相关派生计算。添加股票、开始或停止追踪等操作在执行时读取中心最新行情。
- `MarketSummary.tsx` 独立订阅大盘指数、组合收益、持仓数量和更新时间；指数仅在选中的指数行情或选择项变化时收到通知。
- `WatchlistRow` 按股票 ID 订阅行情；列表从共享派生缓存取得指标后传入行组件。单股计算缓存依赖股票配置、价格、昨收、币种、账本、汇率、调整项和市场日期；更新时间变化不重算收益，结果相同时复用引用。
- 列表仍订阅行情集合，负责排序、筛选与质量统计；因此列表容器仍会重新计算，不能声称任何行情变化都只有一行执行。未变化股票行可以利用原有 memo 和稳定指标引用跳过父级引起的渲染；时效状态定时更新仍可触发行更新。
- 收益分析和追踪弹窗直接读取中心行情；追踪弹窗的 `trackingQuotes` 副本已移除。演示数据的完整快照包含仍在追踪的股票，避免完整刷新清掉其行情。
- 中心随业务状态移除不再属于自选、活动追踪配置或已选指数的行情；在途旧请求也按最新归属过滤，防止被删除股票重新进入快照。
- 第 2 步暂时通过 App/Context 传入乐观业务状态；第 3 步已将该状态的所有权移到中心。第 4 步已移除组合选择器的过渡参数，统一读取中心快照。

## 第 3 步的边界

- App 的业务状态与追踪档案索引改为读取中心快照，移除本地 AppState 副本、状态监听和各回调中的 setState。主进程仍是权威持久化入口。
- 中心提供 commands.update(reducer) 与 commands.archive(prepare)。窗口内修改按顺序执行，执行时读取最新已确认状态，再交给原有 revision/增量 IPC 保存；不会在点击时构造整份旧快照后排队覆盖。
- 普通保存、停止追踪并归档、删除股票并归档、删除历史周期共用队列。尚有旧调用方时，stockApi.saveState/归档接口也经过队列并检查版本。
- 中心只乐观发布正在执行的操作，后续排队操作在轮到时反馈。乐观删除不清理行情缓存；成功确认后的状态才清理，失败能恢复已有行情。
- 保存失败先恢复最新已确认状态，再向主进程重新同步；不自动重放失败命令。同步仍失败时，后续修改必须先同步成功才能保存。状态快照提供 writes.pendingCount、activeOperation、lastError，暂未增加新的界面提示控件，沿用 App 的错误提示。
- 自选开关、排序、分组、设置、账户、交易、公司行动、追踪修改均改为函数式写入。设置仅合并本次改变的顶层字段；交易账本与追踪草稿在排队期间发生相关数据变化时会拒绝旧草稿，提示重新确认。表单草稿本身仍由组件维护。
- 添加股票后的价格补充在请求返回后重新读取中心，并确认原股票对象未被替换；不会用早先保存结果覆盖整个状态。停止追踪/删除股票在执行归档时重新读取档案，归档索引也由中心统一更新。
- 演示环境保存和归档递增 revision，与中心旧版本拒绝规则一致。日历、汇率通过主进程原有推送同步，App 不再从请求返回值拼接另一份业务状态。
- 本步骤只串行化当前渲染窗口的写入，其他窗口或主进程后台任务仍由原有 revision 冲突机制处理。未改持久化格式、IPC 协议、收益计算口径和界面布局。

## 第 4 步的边界

- 删除完整状态的 SecuritiesAccountContext/Provider 和未使用的 commitAccountState 接口。StockAccountScope 只保留账户选择和展示逻辑，从中心订阅账户配置、相关费用设置及当前股票账本。
- 新增 useAppStateField、useAppSettings、useStockTradingBook、useStockTrackingProfile 和 useAccountFeeData。多字段设置按字段引用比较，账户费用数据仅包含手续费及上次选择账户相关设置；共享账户工具的参数类型相应收窄，计算逻辑保持原样。
- WatchlistTable、StockTrackingDialog、PortfolioPerformanceDialog、SettingsMenu、账户及费用管理弹窗直接订阅需要的业务字段，App 不再向这些模块下发整份状态或业务数据集合。股票行按 quoteId 读取行情、交易账本和追踪档案。
- 账户/费用管理移除本地整份初始 AppState，只初始化本模块的可编辑草稿；校验账户绑定、历史交易及费用方案时读取中心当前字段。账户及费用草稿保存时比较打开/上次保存时的字段基线，跨窗口同字段修改会拒绝旧草稿；成功保存后更新草稿与基线。费用绑定及账户删除/停用规则在命令实际执行时按最新账户、账本和公司行动记录再次校验，覆盖排队期间新增关联数据的情况。交易、持仓等表单的未保存草稿及交互选择仍保留在组件内，不会被行情推送重置。
- App 仅订阅主框架及尚未迁移模块所需的自选、追踪配置和少量设置。事件处理时从中心取得快照；提交后仍由第 3 步队列按最新已确认状态执行，并检查排队期间的相关草稿冲突。
- SettingsMenu 和图表设置回调改为提交 Partial<AppSettings>，只合并用户本次修改的顶层字段。App 无需订阅完整设置对象来计算差异。
- 组合派生选择器仅接受中心快照；根据自选、账本、汇率、调整项、行情和各市场日期缓存结果。主题、归档索引、保存进度等无关变化保持组合结果引用不变。命令预览在自选分组归属没有变化时保留原自选数组引用。
- 为删除 Context，同步迁移 AI 导入模块的账户订阅及 AI 做 T 模块的账户入口引用；其余可选模块和辅助窗口的完整迁移仍属于第 6 步。
- 列表排序/汇总、收益分析、追踪列表仍需订阅相应集合，App 也仍向筛选/扫描模块传递其所需数据。父组件渲染、定时状态更新仍可能让子组件执行，不能据此声称每次修改都只渲染一个组件。

## 第 5 步的边界

- 新增窗口级详情资源中心，统一保存数据、加载状态、错误及更新时间。同一资源键共享在途请求与快照；股票、资源种类、K 线周期和请求条数共同决定键，历史不同条数不混用。缓存最多保留 200 个条目，淘汰无订阅、无消费且无在途任务的旧条目；活跃条目可暂时超过此上限。
- K 线、资金流向、板块指数、盘口、股东、财报、海外基本面、估值、公司行动候选和追踪历史周期接入中心。对应详情组件移除本地响应数据副本及模块级缓存，保留标签、账户选择、操作进度、编辑草稿和预览等交互状态。财报及公司行动 AI 总结完成后更新共享快照。
- 自选详情和每日扫描不再分别缓存相同 K 线。追踪日线与分时按各自资源独立加载，任一路失败保留该资源上次成功的数据，错误仍在追踪详情提示。已有一分钟分时不会被失败后的五分钟回退结果覆盖。
- 组件通过 Hook 声明消费与刷新需求；中心每个资源只保留一个刷新定时器，按消费方中较短的需求间隔及原有交易时段规则调度。最后一个消费方退出后停止自动刷新。不同窗口仍各有资源中心，未改主进程数据源、盘口 Hub 合并及请求频率下限。
- 保留分时/五日、资金流向、板块原有缓存有效期；历史 K 线、股东、估值和公司行动候选使用五分钟窗口缓存，盘口使用 750ms。财报、海外基本面和历史追踪周期保留至手动更新、失效或淘汰；底层持久化缓存仍由原服务管理。手动刷新绕过窗口缓存；遇到普通读取在途时，合并排队执行一次强制刷新。
- 单股缓存清理按实际清理成功的类别失效；全局清理按请求类别失效，临时行情类别映射到 K 线及盘口/资金流向/板块。正在消费的失效资源会重新请求，在途旧结果通过版本标记丢弃，避免清理后的数据被旧响应写回。
- 兼容 stockApi 的详情读取也经过资源中心，但辅助窗口、AI/行情洞察等可选模块仍有局部状态或自行发起请求的路径，完整迁移属于第 6 步。此步骤不表示所有组件已无副本，也不表示跨窗口只发一次网络请求。

## 第 6 步的边界

- 任务栏悬浮详情、托盘概览、菜单栏展开详情移除本地完整 AppState 和行情数组，以及各自的状态/行情事件监听。TaskbarTicker 与托盘使用字段级辅助窗口订阅，行情集合只包含勾选在任务栏显示的股票；详情按 quoteId 订阅股票、行情、账本、收益调整及累计收益。辅助窗口仍分别拥有窗口级中心，通过主进程同步，不是跨窗口共享同一个 JavaScript 对象。
- StockQuoteDetails 不再接收整份状态和行情数组，盘口改用中心刷新需求。保留原本一次读取分时缩略图的行为；盘口仍遵循对应市场交易日历及刷新开关。窗口布局、展开状态、尺寸观察及菜单栏时效提示计时器保留在界面层。
- 市场观察的设置、状态、个股快照移到中心。详情图表直接读取同一个快照和叠加设置，删除子面板回传快照后父组件再次保存的路径，以及旧 settings-store 事件中转。窗口内市场观察推送统一订阅、按消费计数释放；手动生成触发的自身更新事件不会打断当前请求。重新启用时保留强制刷新行为。设置写入排队并基于最新设置修改，阈值输入只在本地保存未提交字段。
- AI 开关/配置、个股短期和长期分析、按股票与账户区分的做 T 历史接入中心。加载历史结果不会触发 AI 生成，只有显式操作才生成；配置保存后更新中心状态，删除 ai:enabled-changed 自定义事件路径。分析进度、操作错误和按钮忙碌状态仍属于交互状态。
- AI 助手会话列表按查询词缓存、会话及消息按会话 ID 缓存。创建、重命名、删除、清空及发送/重试通过模块门面更新中心。流式事件在窗口内统一监听和按帧合并，切换会话不把旧会话结果写入新会话；完成事件先于发送返回时保留完成内容，并将用户消息放到对应回答前面。输入草稿、提及列表、搜索词和来源预览仍在组件内。
- 记忆身份状态、事实列表、资料库、文档、处理任务及维护候选存入中心。资源键包含身份切换版本、profileId、libraryId 或 conversationId，切换身份后旧异步响应不能写入重新进入的身份资源。写操作后的重读先淘汰旧请求，保留已有数据显示，避免复用写入前发起的读取；普通元数据刷新不会卸载正在使用的子面板。
- 资料上传和后台处理的操作流程继续由资料库模块控制：上传文件/令牌/未保存编辑草稿、进度、检索结果及来源预览不作为共享持久数据保存。处理任务轮询仍按该工作流的可见生命周期执行，结果写回中心，读取任务集合时不再另存 jobsRef 数据副本。模块业务 API、远端记忆服务和主进程持久化格式未改变。
- 可选功能仍受原编译开关和 API 可用性约束；市场观察浏览器演示数据按需导入。缓存、事件合并和写入队列的保证限于当前渲染窗口，未引入新的跨窗口锁、协议或存储系统。

第 7 步已完成下述旧路径清理、代码审计及 Luna 只读静态验收。该步骤时遗留的每日扫描与独占运行元数据分别在第 8、9 步迁移；各步的静态与运行验证边界仍分别保留。

### 旧路径与生命周期核对

- 搜索 `src` 中的完整状态/行情本地状态声明、`onStateUpdated`、`onQuotesUpdated`、`saveState` 和 `window.*`，并追踪组件调用。已迁移展示组件无直接 `window.stockApi` 访问，也无上述三个旧状态读写接口的调用。底层状态与行情监听集中在 `center.ts`，`api.ts` 负责选择桌面或演示 transport。

## 第 8 步的边界

- 窗口中第一个消费方注册进度事件，最后退出时解除监听；关闭弹窗不取消主进程任务。重开先订阅后重新读取结果与状态，迟到的状态初始化不能覆盖较新推送。主进程启动时异步加载 latest.json 后的首次 completed 推送也会重读先前为 null 的结果。
- 主进程仍以 runningTask 合并实际扫描，renderer 额外合并同窗口连续调用的 Promise。扫描开始、运行状态进入新任务和完成/失败推送会淘汰旧读取；成功回包通过清理代际、任务活动版本及生成时间保护发布，再重读权威结果。后续读取失败保留上次成功数据，不会将已成功的无推送 demo 更新丢掉。浏览器 demo 仍返回固定演示数据，不新增模拟扫描策略。
- 资源按需从现有 registry 取得，闲置被 LRU 淘汰后重进会重新取得当前条目，不长期持有已淘汰资源的引用。
- 全局 data-snapshots 清理在删除文件前调用主进程扫描服务的 clearForCache，增加代际并清空内存结果与状态；旧扫描在等待初始化、获取行情或日 K 后会检查代际，不再发出进度/失败/完成推送或重建 latest.json，迟到的磁盘加载也不能恢复内存快照。renderer 同时设置清理代际并失效资源，忽略旧任务回包；旧 pending 命令未结束时连续调用不会提前解除清理标记。新明确命令允许读取本次状态与进度，结果屏蔽直到该新命令成功后才恢复；失败保持结果为空。未改变现有清理后自动重启行为，不取消已发出的网络请求。
- 清理后同代际任务 A 成功的回包即使晚于外部任务 B 的 running 推送，仍允许重新读取主进程最新成功结果；B 尚未成功或失败时 A 属于应保留的上次成功数据。活动版本限制回包直接发布，权威重读保留已成功的更新外部任务结果。
- 清理到自动重启的短暂窗口内，主进程仍保留单任务合并：旧 runningTask 未结束时 run 返回同一 Promise，不立即并发启动新代际；旧任务结束并因代际失效后，后续明确 run 才能启动新任务并写入新结果。
- 审计主进程服务确认：扫描只由原 run 入口启动，未新增自动调度；服务失败保留旧成功快照，结果写入原 latest.json。主进程其他模块读取原结果，普通扫描的任务合并规则、并发数、扫描条件和数据源保持原样；缓存清理时旧代际失效见上文。
- 第 9 步接续集中独占运行元数据：optionalModulesState、cacheSummary、GitHub 同步设置与完成通知；它们属于业务/运行数据，不能归类为交互草稿。

## 使用约定

展示组件通过 `useStockQuote(quoteId)` 等 Hook 读取和订阅，不将共享快照再次复制进本地 `useState`。同一窗口共用一个中心；不同窗口通过主进程同步。

中心内部的选择器会在快照发布时进行比较，只有结果改变才通知订阅者。当前尚未建立按键索引的通知队列，不应将其描述为所有选择器都不需要参与比较。

纯显示、表单草稿、当前标签、展开状态继续由组件维护。业务写入通过 `dataCenter.commands` 提交函数式修改；完整旧快照 API 仅作兼容，不应直接修改中心快照。
