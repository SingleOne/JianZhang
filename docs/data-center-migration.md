# 组件数据中心迁移

目标：主进程维护权威数据，每个渲染窗口提供共享快照与按范围订阅。组件读取中心数据，提交明确修改命令，仅在本地保留交互状态和编辑草稿。

## 第 1 步的边界

- `src/lib/data-center/store.ts` 提供快照和选择器订阅。同一次发布先提交快照，再通知选择结果改变的订阅者；选择结果不变时保留引用。
- `center.ts` 统一接收现有状态和行情事件，复用 `state-client.ts` 的 revision 与增量 IPC 逻辑。中心复用已有状态对象，不进行整份深拷贝。
- `src/lib/api.ts` 导出窗口级 `dataCenter`；原 `stockApi` 改为兼容门面。旧组件可逐步迁移，不额外注册底层状态、行情事件监听。
- `hooks.ts` 通过 `useSyncExternalStore` 提供 `useAppData`、`useStockQuote` 和 `useAppSetting`。快照按只读使用；对象或数组派生结果需使用稳定选择器和适当的相等判断。
- `TaskbarTicker` 是首个接入组件，移除了本地 `state`、`quotes` 副本。目前仍订阅完整状态和行情集合；按可见股票进一步缩小范围属于后续步骤。
- 初始化与手动刷新期间若收到行情推送，中心保留推送快照。定向刷新返回的部分数据合并到中心，兼容门面仍返回原请求结果。

当前只统一核心业务状态与行情入口。主窗口 App、账户 Context、详情缓存、模块状态及修改回调尚未迁移，不能将本阶段视为全部细粒度改造完成。

## 使用约定

展示组件通过 `useStockQuote(quoteId)` 等 Hook 读取和订阅，不将共享快照再次复制进本地 `useState`。同一窗口共用一个中心；不同窗口通过主进程同步。

中心内部的选择器会在快照发布时进行比较，只有结果改变才通知订阅者。当前尚未建立按键索引的通知队列，不应将其描述为所有选择器都不需要参与比较。

纯显示、表单草稿、当前标签、展开状态继续由组件维护。第 3 步完成前，业务写入仍使用现有 `stockApi.saveState` 与 revision 校验，不应直接修改中心快照。

## 验证记录

第 1 步采用 TypeScript、ESLint、格式和差异静态检查及 Luna 静态复审。回归用例覆盖订阅隔离、快照引用、迟到初始化、定向刷新、推送与刷新竞态、失败保存及取消订阅；用例仅编写并参与类型检查，未执行测试、生产构建或界面验证。
