# 加载性能优化实施方案

## 目标

在不改变行情、基本面、分红融资和 AI 功能行为的前提下，缩短应用启动到首屏可用的时间，减少启动阶段的重复解析与跨进程传输，并让非交易时段启动时也能立即看到最近行情。

本轮只进行静态检查，不主动执行界面验证、生产构建、`npm run build:unpacked` 或正式打包。每个阶段独立提交，便于单独复核和回退。

## 调研基线

基线来自 2026-08-30 对当前代码、已有 `out` 构建产物和本机实际用户数据的只读检查：

- 主渲染 JS：约 1.59 MB，gzip 后约 295 KB。
- 主渲染 CSS：约 507 KB，gzip 后约 61 KB。
- 实际基本面快照：52,909,523 字节，5,558 家公司。
- 实际分红融资快照：2,891,030 字节，1,098 只股票。
- 实际用户状态：925,591 字节，93 只自选股。
- 基本面快照单次 `JSON.parse` 约 205 ms，单次 `structuredClone` 约 224 ms。该数据仅作为当前设备上的微基准，不等同于 Electron 端到端加载时间。
- 现有行情日志中，95 只股票批量请求约 52 ms，114 只股票约 236 ms。行情请求已按市场并行、市场内批量执行，不是当前第一优先级。

## 已确认的问题

1. 主窗口、任务栏行情、任务栏提示窗和托盘弹层共用同一个渲染入口。任务栏行情启用时，小窗口也会解析主应用代码和全部全局样式。
2. 基本面初筛、分红融资、市场扫描和股票追踪等非首屏弹窗仍由 `App.tsx` 同步导入，对应样式由 `main.tsx` 无条件加载。
3. `QuoteRuntime` 每次启动都从空行情数组开始；非交易时段不会自动刷新，因此无法立即回显最后一次成功行情。
4. 启动后会读取完整基本面和分红融资快照，将完整对象通过 IPC 发送给渲染进程，再由前端执行全量筛选和同行排名。
5. 市场观察、AI 和做 T 参考模块安装完成后才创建主窗口，可选模块处于窗口关键路径上。
6. 同一渲染进程中的主题控制器和实际页面会分别请求 Bootstrap，重复传输应用状态。

## 实施顺序

### 1. 拆分窗口渲染入口

- 入口文件只负责识别窗口模式。
- 主窗口、任务栏行情、任务栏提示窗和托盘弹层分别动态导入自己的 React 入口与样式。
- 保留共享的主题初始化和确认框能力，但避免非主窗口导入 `App.tsx`。

验收：从静态依赖关系确认任务栏与托盘入口不再同步依赖主应用；TypeScript、ESLint、变更文件 Prettier 和 `git diff --check` 通过。

### 2. 非首屏功能按需加载

- 将基本面初筛、分红融资、市场扫描和股票追踪弹窗改为 `lazy()`。
- 仅在弹窗打开时挂载组件。
- 将功能专属 CSS 移到对应组件或按需入口，避免主入口无条件加载。
- 保持自选表格、标题栏和搜索等首屏核心组件同步加载。

验收：静态依赖关系中非首屏弹窗形成独立动态导入边界；不改变弹窗属性和交互语义。

### 3. 最近行情启动缓存

- 在成功行情刷新后原子保存轻量行情快照。
- 启动时读取缓存并按当前自选、追踪股票和指数范围过滤。
- 缓存只用于即时回显，继续使用行情自带时间字段判断实时、延迟或过期状态。
- 行情缓存不进入用户配置、同步备份或交易账本。

验收：`QuoteRuntime` 初始化时可以获得缓存行情；刷新成功后更新缓存；损坏缓存不会阻止应用启动。

### 4. 基本面与分红融资轻量概览

- 为主列表建立轻量概览数据，包含快照元数据、自选列表实际使用的筛选结果、同行比较和分红融资字段。
- 启动时只读取概览数据并按代码返回需要的记录。
- 完整快照只在打开基本面初筛或分红融资弹窗时加载。
- 数据更新时同步刷新概览；现有安装缺少概览时允许后台一次性生成，不阻塞首屏。
- 如首次生成仍会造成明显主线程阻塞，将解析和计算迁移到 Worker。

验收：`App.tsx` 首屏不再接收完整 52.9 MB 基本面快照，也不再执行全市场筛选；弹窗仍能按需获得完整快照。

### 5. 可选主进程模块延后初始化

- 核心状态、核心 IPC 和窗口管理器先初始化并创建窗口。
- 市场观察、AI、做 T 参考等可选模块在窗口创建后并行安装。
- 初始化期间相关入口显示不可用或初始化状态，避免短暂缺少 IPC 处理器时触发错误。
- 退出流程兼容模块尚未初始化完成的情况。

验收：主窗口创建不再等待可选模块动态导入；模块初始化失败不影响基础行情界面。

### 6. 合并 Bootstrap

- 每个渲染进程只创建一个 Bootstrap Promise。
- 主题控制器和当前窗口页面共享该 Promise。
- 小窗口后续可进一步改用仅包含主题、行情和布局的轻量 Bootstrap。

验收：同一渲染进程不会因为多个组件挂载重复调用 `app:bootstrap`；状态更新订阅行为保持不变。

## 检查与提交规则

每个阶段完成后，由只读 Luna 子 agent 执行：

```powershell
npx tsc --noEmit --pretty false
npm run lint
npx prettier --check <本阶段变更文件>
git diff --check
```

如包含非 TypeScript 文件，增加相应静态语法检查。主 agent 负责修复问题、复核差异和创建最终提交。静态检查结果不代表已完成测试、界面验证、构建、开发预览或打包验证。

## 后续效果验证

只有用户明确要求运行开发预览或构建时，再采集以下端到端指标：

- Electron `ready` 到主窗口 `ready-to-show`。
- 首屏 Bootstrap 应用完成时间。
- 第一批缓存行情展示时间和第一批实时行情更新时间。
- 基本面概览可用时间。
- 主窗口与任务栏窗口各自加载的 JS/CSS 体积。
- 启动稳定后的主进程和各渲染进程内存占用。
