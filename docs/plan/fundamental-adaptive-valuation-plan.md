# 基本面自适应估值与企业类型指标方案

> 文档状态：待评估，尚未授权实施
>
> 编写日期：2026-09-08
>
> 代码基线：`main` 分支，提交 `cb254b4`，应用版本 `13.10.0`
>
> 本文仅定义产品、数据和技术方案，不代表已修改功能代码。

## 1. 方案结论

基本面可以同时展示估值数值、模型结论、适用性提示，以及不同类型企业应优先关注的指标，但不应把 DCF、PE、PB、PCF 等结果直接平均成一个“综合估值分数”。

推荐采用以下结构：

1. 先识别企业的法定组织类型和估值特征标签。
2. 每类企业只指定一个主要估值框架，其余指标用于交叉验证。
3. 同时展示数值、结论、可信度、数据日期和不适用原因。
4. 多个模型结论不一致时明确显示“指标存在分歧”，不强行给出单一结论。
5. 所有结论保持为模型和数据说明，不输出买入、卖出、仓位或收益承诺。

目标形态是一个“企业类型自适应估值面板”，而不是继续增加彼此独立的指标卡片。

## 2. 目标与非目标

### 2.1 目标

- 将现有 DCF、PE、PB、PCF、ROIC、自由现金流和净负债整合到统一估值框架。
- 对普通企业、银行、保险和证券公司分别说明适用与不适用指标。
- 为普通企业预留稳定现金流、重资产、周期和高增长等估值特征标签。
- 在估值结论之前展示公司的主营业务和业务简介，先回答“公司靠什么赚钱”。
- 将当前简化自由现金流升级为可追溯的年度 FCFF。
- 以保守、基准、乐观三种情景展示 DCF 估值区间。
- 明确显示模型假设、数据完整度、数据时点和结论可信度。
- 让基本面界面与长期价值 AI 使用同一份结构化计算结果，避免重复计算和结论漂移。

### 2.2 非目标

- 不把模型估值描述为目标价。
- 不输出具体买卖方向、价格、股数或仓位。
- 不承诺模型估值一定会被市场价格实现。
- 不使用一个未经解释的总分覆盖各模型之间的差异。
- 不对银行、保险和证券公司套用普通企业 FCFF。
- 不在字段缺失时使用零值代替真实缺失值。
- 不仅根据单年利润或单个行业名称作出高增长、周期或稳定现金流判断。
- 不使用 AI 自动编写的内容代替结构化公司业务资料。

## 3. 术语与模型关系

### 3.1 FCFF 与 DCF

FCFF 是可供股东和债权人分配的企业自由现金流；DCF 是把未来现金流折算到当前价值的方法。二者不是互斥关系，目标模型是“以 FCFF 为现金流口径的 DCF”。

```text
未来 FCFF
→ 按 WACC 折现
→ 企业价值
− 净负债
→ 股权价值
÷ 总股本
→ 每股模型估值
```

### 3.2 PCF 与 P/FCF

- 当前应用的 PCF TTM 是总市值相对于最近连续四季度经营现金流的倍数。
- P/FCF 是总市值相对于自由现金流的倍数，当前尚未作为独立指标实现。
- PCF、P/FCF 属于相对估值，适合历史和同行比较；DCF 属于绝对估值，适合估算模型价值。

界面和数据字段必须明确区分 `PCF` 与 `P/FCF`，不得混用名称。

### 3.3 公司业务简介与财报经营总结

“公司业务简介”用于说明公司长期从事什么业务，优先采用结构化公司资料；“管理层讨论与分析”用于说明某一报告期内业务发生了什么变化，来自具体财报。两者不能混为一项：

| 内容         | 来源                           | 更新特点                       | 展示用途                         |
| ------------ | ------------------------------ | ------------------------------ | -------------------------------- |
| 主营业务     | 东方财富结构化公司资料         | 低频变化                       | 顶部一句话说明公司靠什么赚钱     |
| 公司简介     | 东方财富结构化公司资料         | 低频变化                       | 展开后了解产品、历史和业务定位   |
| 工商经营范围 | 东方财富结构化公司资料         | 工商口径，可能明显宽于实际业务 | 次级展开信息，不作为主营业务结论 |
| 管理层讨论   | 最新定期报告及现有按需 AI 总结 | 随报告期变化                   | 解释收入、利润、现金流和业务变化 |

业务简介不参与估值数值计算。主营业务和行业字段可以为企业类型规则提供事实输入，但自由文本 `ORG_PROFILE` 不直接决定估值标签。

## 4. 当前实现基础

### 4.1 已有能力

当前基本面详情已经具备：

- `DcfPanel`：DCF 每股估值、当前价格比较、低于现价提醒和模型口径。
- `InvestmentValueMetrics`：PE、PB、PCF、总市值、自由现金流、ROIC 和净负债。
- 五年 ROE、现金利润质量、行业杠杆、财务排雷和同行比较。
- `organizationType`：`general`、`bank`、`securities`、`insurance`、`other`。
- PE、PB、PCF 的历史分位和行业分位。
- 金融企业对普通企业自由现金流、ROIC、净负债和 PCF 的不适用处理。
- 公司财报库可以按报告生成管理层讨论摘要，但当前没有独立、结构化、无需 AI 的公司业务简介。

应继续复用现有 `InvestmentValueMetrics` 及其计算源，不能在基本面内再复制一套 PE、PB、PCF 逻辑。

### 4.2 当前 DCF 口径

现有模型使用：

```text
基础自由现金流 = 最近三年（经营现金流 − 资本开支）的算术平均值
预测期 = 5 年
折现率 = 固定 10%
永续增长率 = 固定 3%
股权价值 = 企业价值 − 净负债
```

该模型可以继续作为旧快照的兼容结果，但应标记为“简化现金流 DCF”，不能在升级后称为严格 FCFF-DCF。

### 4.3 当前数据缺口

当前年度快照没有完整保存以下 FCFF 输入：

- EBIT 或构造 EBIT 所需的详细损益项目。
- 所得税费用和利润总额的原始值。
- 折旧、无形资产摊销和使用权资产摊销。
- 每个年度的经营性流动资产和经营性流动负债。
- 每个年度的营运资本及其同比变化。
- 计算动态 WACC 所需的无风险利率、市场风险溢价、Beta 和历史债务成本。

因此，当前已持久化快照不能直接严格计算 FCFF，需要扩展数据生成脚本和快照结构。

## 5. 企业分类方案

企业分类分成两层，避免用一个标签描述所有情况。

### 5.1 第一层：法定组织类型

沿用现有东方财富 `ORG_TYPE` 映射：

| 类型     | 识别方式           | 普通 FCFF-DCF |
| -------- | ------------------ | ------------- |
| 普通企业 | `general`、`other` | 可评估适用性  |
| 银行     | `bank`             | 不适用        |
| 证券     | `securities`       | 不适用        |
| 保险     | `insurance`        | 不适用        |

这一层属于硬分类，优先级最高。

### 5.2 第二层：普通企业估值特征标签

普通企业允许具有多个标签，不强制互斥：

```ts
type ValuationProfileTag =
  'stable-cash-flow' | 'asset-heavy' | 'cyclical' | 'high-growth' | 'cash-flow-volatile'
```

推荐识别原则：

- `cyclical`、`asset-heavy` 首先来自可维护的行业映射，再由财务数据验证。
- `stable-cash-flow`、`cash-flow-volatile` 根据至少五年现金流完整度、正值年数和波动程度识别。
- `high-growth` 根据至少三年收入增长、利润增长、研发投入和现金流阶段综合识别。
- 每个标签必须携带 `reasons`，在界面上可以解释为何得到该标签。
- 当行业映射和财务特征冲突时，只显示特征事实，不自动下确定性标签。
- `MAIN_BUSINESS` 和结构化行业字段可以参与行业映射；`ORG_PROFILE` 只供用户阅读，不直接参与规则判断。

首期不建议允许模型或 AI 自由生成企业类型。分类必须由确定性规则计算。

## 6. 企业类型与指标映射

| 企业类型或标签     | 主要估值和质量指标                              | 辅助验证                        | 降权或不适用项                   | 重点提示                       |
| ------------------ | ----------------------------------------------- | ------------------------------- | -------------------------------- | ------------------------------ |
| 稳定现金流普通企业 | FCFF-DCF、ROIC−WACC、FCFF 稳定性                | PE、PCF、P/FCF、现金转换率      | 无                               | DCF 对增长率和 WACC 敏感       |
| 重资产企业         | FCFF、ROIC−WACC、资本开支和净负债               | PB、EV/EBITDA、折旧覆盖         | 单纯 PE 降权                     | 区分维持性与扩张性资本开支     |
| 周期企业           | 周期中枢 FCFF、PB、净负债                       | EV/EBITDA、利润和现金流周期位置 | 单年 PE、单年 DCF 降权           | 不得直接外推景气高点或低点     |
| 高增长企业         | 收入、毛利率、研发投入、FCFF 趋势、情景 DCF     | PS、PE、现金消耗和稀释          | 单点 DCF 结论降权                | 远期假设占比高，估值区间应更宽 |
| 银行               | PB、ROE、净息差、不良率、拨备覆盖率、资本充足率 | 股息率、成本收入比              | 普通 FCFF、PCF、普通净负债不适用 | 需银行专用数据后才输出完整结论 |
| 保险               | P/EV、ROE、新业务价值、偿付能力                 | 综合成本率、投资收益率          | 普通 FCFF-DCF 不适用             | 需内含价值和保险专用数据       |
| 证券               | PB、ROE、净资本和杠杆                           | 经纪、投行、自营收入结构        | 普通 FCFF-DCF 降权或不适用       | 盈利周期强，单年 PE 容易误导   |

“主要指标”表示本类型结论的首要依据；“辅助验证”只用于确认、补充或指出冲突，不能与主模型简单平均。

## 7. 统一估值结果模型

### 7.1 模型角色

每个估值模型都应声明角色：

```ts
type ValuationModelRole = 'primary' | 'secondary' | 'informational'
```

- `primary`：该类型企业的主要估值依据。
- `secondary`：用于历史、同行或现金质量交叉验证。
- `informational`：只展示事实，不参与总体结论。

### 7.2 可用状态

```ts
type ValuationAvailability =
  'available' | 'not-applicable' | 'insufficient-data' | 'stale-data' | 'unstable-input'
```

每个非 `available` 状态必须提供固定原因码和用户可读说明，不能只显示 `--`。

### 7.3 结论状态

建议使用中性、可验证的模型结论：

```ts
type ValuationConclusion =
  | 'below-model-range'
  | 'within-model-range'
  | 'above-model-range'
  | 'low-relative-multiple'
  | 'middle-relative-multiple'
  | 'high-relative-multiple'
  | 'conflicting-signals'
  | 'unavailable'
```

界面文案使用“低于模型估值区间”“位于模型估值区间”“高于模型估值区间”，不直接使用“应该买入”“应该卖出”。

### 7.4 可信度

```ts
type ValuationConfidence = 'high' | 'medium' | 'low' | 'unavailable'
```

可信度至少考虑：

- 财务数据是否完整、是否过期。
- 有效 FCFF 年数和正值年数。
- FCFF 波动程度。
- 企业是否具有周期或高增长标签。
- 三种情景估值区间是否过宽。
- 主要模型与辅助指标是否明显冲突。

可信度描述的是模型输入稳定性，不表示股价达到估值的概率。

## 8. 严格 FCFF 计算口径

### 8.1 年度 FCFF

推荐使用以下主公式：

```text
调整后 EBIT
= 营业利润
+ 利息费用
− 明确识别的非经营性投资收益、公允价值变动和资产处置收益

有效税率
= 所得税费用 ÷ 利润总额

经营性营运资本
= 非现金经营性流动资产
− 非有息经营性流动负债

年度 FCFF
= 调整后 EBIT ×（1 − 有效税率）
+ 折旧摊销
− 资本开支
− 经营性营运资本增加额
```

税率异常、利润总额非正或关键调整项缺失时，保留原始字段并返回明确原因，不把异常税率直接带入模型。

### 8.2 营运资本

推荐按明细构造，而不是直接使用“流动资产−流动负债”：

```text
经营性流动资产候选
= 应收票据及账款
+ 预付款项
+ 存货
+ 合同资产
+ 其他可确认的经营性流动资产

经营性流动负债候选
= 应付票据及账款
+ 合同负债或预收款
+ 应付职工薪酬
+ 应交税费
+ 其他可确认的经营性流动负债
```

货币资金、交易性金融资产、短期借款、一年内到期有息债务等不进入经营性营运资本。

为了计算五个年度的 `Δ经营性营运资本`，至少需要六个年度的资产负债表数据。

### 8.3 基础 FCFF 正常化

首期推荐保持规则简单、透明：

- 稳定现金流企业：最近三年有效 FCFF 算术平均值。
- 周期企业：最近五年有效 FCFF 平均值，并明确标记“五年不一定覆盖完整周期”。
- 高增长或现金流波动企业：仍展示年度 FCFF，但降低 DCF 可信度，不通过复杂拟合制造精确结果。
- 最近三年 FCFF 不完整或正常化结果不为正时，不生成基准 DCF。

后续如需使用中位数、去极值或行业周期模型，应单独评审，不能静默改变历史估值。

## 9. WACC 与三情景 DCF

### 9.1 WACC

```text
股权资本成本 Ke = 无风险利率 + Beta × 市场风险溢价
税前债务成本 Kd = 利息费用 ÷ 平均有息债务
WACC = Ke × 股权权重 + Kd ×（1 − 税率）× 债务权重
```

WACC 的每项输入都必须显示来源日期。Beta 样本不足、债务成本失真或市场参数缺失时，模型应降级到“参数不完整”，不能静默回退为固定 10% 并继续显示为严格 WACC。

如产品希望保留固定折现率模式，应明确命名为“固定折现率情景”，与“公司 WACC 情景”分开。

### 9.2 三种情景

建议默认同时展示：

| 情景 | 预测增长率     | 折现率    | 永续增长率     | 用途     |
| ---- | -------------- | --------- | -------------- | -------- |
| 保守 | 基准增长率下调 | WACC 上调 | 基准值下调     | 压力情景 |
| 基准 | 正常化增长率   | 公司 WACC | 长期基准       | 主要参考 |
| 乐观 | 基准增长率上调 | WACC 下调 | 基准值小幅上调 | 上行情景 |

具体上下调幅度作为可配置常量保存。首版建议值为：

- 保守：增长率 `−3` 个百分点、WACC `+1.5` 个百分点、永续增长率 `−0.5` 个百分点。
- 乐观：增长率 `+3` 个百分点、WACC `−1` 个百分点、永续增长率 `+0.5` 个百分点。
- 所有情景必须满足永续增长率严格低于折现率。

这些参数属于方案建议，实施前需要用户确认。

### 9.3 区间结论

不使用单一基准估值直接判断高低，优先使用三情景区间：

- 当前价格低于保守情景：`低于模型估值区间`。
- 当前价格位于保守和乐观情景之间：`位于模型估值区间`。
- 当前价格高于乐观情景：`高于模型估值区间`。
- 任一关键情景不可计算：显示已有结果并降低可信度，不补造缺失结果。

## 10. 相对估值与交叉验证

### 10.1 相对估值

继续展示：

- PE TTM、PB、PCF TTM。
- 当前值相对自身近五年历史分位。
- 当前值相对快照日同行业分位。
- PCF/PE 剪刀差和多年现金利润背离。

可以在 FCFF 完成后增加 P/FCF，但必须与当前 PCF 分开：

```text
P/FCF = 当前总市值 ÷ 最近十二个月或正常化自由现金流
```

当自由现金流不为正时，P/FCF 不适用，不显示负倍数作为“低估”。

### 10.2 默认分位说明

建议将历史和行业分位划分为：

- `0%—30%`：相对低位。
- `30%—70%`：相对中位。
- `70%—100%`：相对高位。

分位低只表示相对自身历史或同行倍数较低，不自动等于内在价值低估。

### 10.3 指标冲突

典型冲突必须单独提示，例如：

```text
FCFF-DCF：当前价格低于模型区间
PCF 历史分位：82%，处于相对高位
ROIC−WACC：为正
FCFF 稳定性：较低

综合说明：模型估值与现金流倍数存在分歧，且 FCFF 波动较大，可信度为中等。
```

“指标存在分歧”本身就是有效结论，不要求程序强行选择一边。

## 11. 界面方案

### 11.1 页面位置

在基本面详情顶部增加“公司业务简介”，随后将现有 `DcfPanel` 和 `InvestmentValueMetrics` 编排为统一的“估值与适用性”区域。共享的 `InvestmentValueMetrics` 继续保留，由新的基本面容器负责组织，不复制内部计算。

建议页面顺序：

```text
公司业务简介
→ 基本面筛选结论
→ 估值与适用性
→ 企业质量
→ 财务排雷
→ 同行比较
→ 五年财务明细
```

### 11.2 公司业务简介

业务简介单独放在估值区域之前，默认保持紧凑：

```text
┌ 公司业务简介 ─────────────────────────────────────────────┐
│ 主营业务：茅台酒及系列酒的生产与销售                      │
│ 公司简介：贵州茅台酒股份有限公司……          [展开]        │
│ 行业：白酒 · 地区：贵州                                   │
│ 来源：东方财富公司资料 · 获取于 2026-09-08                 │
└───────────────────────────────────────────────────────────┘
```

展示规则：

- `MAIN_BUSINESS` 作为醒目的一句话主营业务。
- `ORG_PROFILE` 默认显示两至四行，支持“展开/收起”，不另行生成 AI 改写版本。
- `BUSINESS_SCOPE` 标记为“工商经营范围”，默认折叠，避免被误认为实际主营业务。
- 同时显示行业、地区、来源和获取时间；源数据没有业务资料更新时间时，不伪造更新时间。
- 清理开头空白、重复换行和明显的空占位符，但保留来源原文语义。
- 内容缺失时显示“公司业务资料暂未提供”，不使用财报 AI 总结自动补位。
- 当前财报库的管理层讨论可以作为“最新经营变化”独立入口，但不能覆盖稳定业务简介。

### 11.3 估值区域布局草图

```text
┌ 估值与适用性 ─────────────────────────────────────────────┐
│ 普通企业 · 稳定现金流 · 重资产                            │
│ 主模型：FCFF-DCF    可信度：中等    数据截止：2025 年报   │
├───────────────────────────────────────────────────────────┤
│ 保守估值       基准估值       乐观估值       当前股价      │
│ ¥xx.xx         ¥xx.xx         ¥xx.xx         ¥xx.xx       │
│ 当前价格：位于模型估值区间                                │
├───────────────────────────────────────────────────────────┤
│ 主要依据：正常化 FCFF / WACC / ROIC−WACC                  │
│ 辅助验证：PE / PB / PCF 的历史与行业分位                   │
├───────────────────────────────────────────────────────────┤
│ 提示：FCFF 波动较大；PCF 位于历史高位，指标存在分歧。      │
├───────────────────────────────────────────────────────────┤
│ [展开模型明细] 年度 FCFF、营运资本、三情景假设和计算过程  │
└───────────────────────────────────────────────────────────┘
```

### 11.4 展示状态

每个指标统一支持：

- `主要`：本类型企业的核心指标。
- `辅助`：只用于验证或补充。
- `不适用`：模型不适用于该组织类型。
- `数据不足`：理论适用，但字段不完整。
- `数据过期`：存在结果，但不能视为当前数据。

不适用和数据不足必须区分。银行的普通 FCFF 是“不适用”，普通企业缺少折旧数据是“数据不足”。

### 11.5 颜色和文字

- 所有文字不低于 `12px`，包括标签、模型说明和风险提示。
- 收益、收益率和正负差额继续遵守：正数红色、负数绿色、零值中性色。
- 估值高低不要直接复用涨跌颜色；模型风险使用橙色或中性警示色。
- 页面固定显示“模型估值，不代表目标价或买卖建议”。

## 12. 数据获取扩展

### 12.1 公司业务资料

现有东方财富数据接口 `RPT_F10_BASIC_ORGINFO` 已核对到以下字段：

| 字段             | 含义         | 方案用途             |
| ---------------- | ------------ | -------------------- |
| `MAIN_BUSINESS`  | 主营业务     | 顶部一句话摘要       |
| `ORG_PROFILE`    | 公司简介     | 可展开的业务介绍原文 |
| `BUSINESS_SCOPE` | 工商经营范围 | 次级折叠信息         |
| `INDUSTRYCSRC1`  | 证监会行业   | 行业展示和分类辅助   |
| `PROVINCE`       | 所在地区     | 基础标签             |

以 `600519.SH` 进行只读核对时，接口能够返回主营业务、公司简介和经营范围。该接口尚未接入当前基本面快照，正式实施时仍需完成全市场覆盖率、文本长度和空值诊断。

业务资料建议随基本面更新流程一起获取并持久化，不应在每次打开详情时重复请求。保存 `fetchedAt`、来源名称和可用的源更新时间；如果源更新时间缺失，只显示获取时间。

现有财报 AI 总结中的 `managementDiscussion` 保持独立，它是特定报告的经营变化总结，不作为 `ORG_PROFILE` 的回退来源。

### 12.2 普通企业 FCFF 候选字段

现有东方财富详细报表接口已核对到以下候选字段：

| 报表                        | 候选字段                                                              | 用途                               |
| --------------------------- | --------------------------------------------------------------------- | ---------------------------------- |
| `RPT_F10_FINANCE_GINCOME`   | `OPERATE_PROFIT`、`TOTAL_PROFIT`、`INCOME_TAX`、`FE_INTEREST_EXPENSE` | EBIT 和有效税率                    |
| `RPT_F10_FINANCE_GINCOME`   | 投资收益、公允价值变动、资产处置等字段                                | 非经营性损益调整                   |
| `RPT_F10_FINANCE_GCASHFLOW` | `FA_IR_DEPR`、`IA_AMORTIZE`、`USERIGHT_ASSET_AMORTIZE`                | 折旧摊销                           |
| `RPT_F10_FINANCE_GCASHFLOW` | `CONSTRUCT_LONG_ASSET`                                                | 资本开支                           |
| `RPT_F10_FINANCE_GBALANCE`  | 应收、预付、存货、合同资产等                                          | 经营性流动资产                     |
| `RPT_F10_FINANCE_GBALANCE`  | 应付、合同负债、职工薪酬、税费等                                      | 经营性流动负债                     |
| `RPT_F10_FINANCE_GBALANCE`  | 货币资金和有息债务                                                    | 剔除金融项目、计算净负债和债务成本 |

上述字段只完成了接口存在性和单股返回核对。正式实施前必须对普通 A 股最近六年数据进行覆盖率诊断，再决定哪些字段可以成为硬依赖。

### 12.3 金融企业专用指标

银行、保险和证券专用指标应单独做数据源评估，不能从普通企业三张表强行推导。

第一阶段如果没有可靠数据，只显示：

- 企业类型。
- 当前可用的 PB、ROE、PE 等事实指标。
- 推荐关注的专用指标清单。
- “专用数据尚未接入”的明确提示。

不得为了界面完整而填充推测值。

## 14. 兼容与持久化

- 新增 FCFF 字段时提升基本面快照 schema 版本，并继续解析旧版本。
- 公司业务资料随基本面快照持久化；旧快照缺少该字段时只显示资料缺失提示，不阻断原有估值展示。
- 旧快照仍可展示现有简化 DCF，但应标记模型版本和数据不足。
- 新 schema 必须同步更新生成器、共享类型、解析器、过期判断、测试、概览索引、AI 上下文和所有 UI 消费方。
- 更新成功后继续原子替换用户目录中的 `fundamentals/snapshot.json`。
- 任一阶段失败时保留上一份有效快照，不留下半写入数据。
- 估值结果应保存 `modelVersion` 和假设版本，便于解释同一股票前后估值变化。

## 15. 与长期价值 AI 的关系

长期价值 AI 只接收应用已计算完成的结构化结果，包括：

- 企业类型和估值标签。
- 结构化主营业务和公司简介，以及它们的来源和获取时间。
- 主模型、辅助模型和不适用模型。
- 三情景估值、当前价格位置和可信度。
- 关键假设、数据日期和风险提示。
- 模型之间的冲突事实。

AI 不得自行改变增长率、WACC 或永续增长率，也不得生成第二套目标价。应用计算不可用时，AI 只能说明不适用或数据不足。

## 16. 分阶段实施建议

### 阶段 A：统一展示与适用性

估值计算只使用当前已有数据，同时接入轻量的结构化公司业务资料：

- 获取并持久化 `RPT_F10_BASIC_ORGINFO` 的主营业务、公司简介、经营范围、行业和地区字段。
- 在基本面顶部增加“公司业务简介”，支持简介和工商经营范围展开。
- 新增统一“估值与适用性”容器。
- 整合现有 DCF 与 `InvestmentValueMetrics`。
- 展示法定组织类型、主要/辅助/不适用状态。
- 增加模型结论、数据时点、分歧和风险提示。
- 金融企业先展示推荐关注项，不伪造专用指标。

除公司业务资料外，该阶段不增加新的财务计算输入，也不改变当前 DCF 计算结果。

### 阶段 B：严格 FCFF 数据和计算

- 对详细财务接口执行全市场六年覆盖率诊断。
- 扩展损益、现金流和资产负债字段。
- 计算并保存年度 FCFF 明细。
- 增加 FCFF 完整度、波动和不可用原因。
- 保留简化 DCF 兼容路径，但新结果明确区分模型版本。

### 阶段 C：WACC 与三情景 DCF

- 接入并显示 WACC 的每项输入和日期。
- 生成保守、基准、乐观三情景。
- 使用估值区间判断当前价格位置。
- 增加敏感性和可信度计算。

### 阶段 D：金融企业专用估值

- 分别评估银行、保险和证券数据源。
- 每类企业独立定义数据、模型和验收标准。
- 专用指标未完整接入前保持“不适用/未接入”，不复用普通企业 FCFF。

各阶段可以独立提交和验收。用户可以只选择阶段 A，也可以批准完整路线。

## 17. 验收标准

### 17.1 通用

- 同一份输入只产生一份结构化估值结果，UI 与 AI 不重复计算。
- 每个数值可以追溯到报告年度、数据日期和模型版本。
- 不适用、数据不足、数据过期和输入不稳定能够明确区分。
- 多模型冲突时显示冲突，不隐藏或强行平均。
- 不出现目标价、买卖指令、仓位或收益承诺。
- 所有界面文字不低于 `12px`。
- 收益及收益率颜色遵守项目现有正红、负绿、零中性规则。

### 17.2 公司业务简介

- 主营业务、公司简介和工商经营范围使用结构化源字段，不依赖 AI 生成。
- 主营业务与工商经营范围的标签和层级清晰，不将宽泛经营范围描述为实际主营业务。
- 公司简介支持展开和收起，所有文字不低于 `12px`。
- 界面显示数据来源和获取时间，不伪造源更新时间。
- 字段缺失、请求失败或旧快照不影响其他基本面和估值功能。
- 公司业务简介不直接改变 DCF、企业标签或总体估值结论。

### 17.3 普通企业 FCFF

- 年度 FCFF 每个组成项均可查看。
- 五年 FCFF 至少需要六年资产负债表支持营运资本变化。
- 关键字段缺失时返回原因，不以零代替。
- 金融企业不会进入普通 FCFF 计算。
- 三情景均满足永续增长率低于折现率。
- 企业价值只在 FCFF 模型下扣除一次净负债。

### 17.4 结论

- 当前价格低于、位于或高于模型区间的方向计算一致。
- PE、PB、PCF 分位只描述相对位置，不自动等于低估或高估。
- 可信度只描述数据和模型稳定性，不描述股价实现概率。
- 指标结论冲突时输出可复核的冲突事实。

## 18. 静态验证计划

功能实施完成后按项目规则只主动执行静态检查，不主动运行界面验证和 `npm run build:unpacked`。

计划中的自动化验证包括：

- FCFF 各组成项和缺失传播单元测试。
- 公司业务资料解析、文本归一化、旧快照兼容和缺失状态测试。
- 营运资本同比变化测试。
- WACC 和三情景 DCF 方向测试。
- 企业类型与指标适用性测试。
- 估值区间与当前价格结论测试。
- 多模型冲突和可信度测试。
- 快照 schema、解析、过期状态和概览索引测试。
- `git diff --check`、ESLint、TypeScript 等静态检查。

是否运行完整测试、生产构建、开发预览或正式打包，由用户另行决定。

## 19. 主要风险

1. **伪精确风险**：DCF 终值对 WACC 和永续增长率非常敏感，必须同时展示区间和假设。
2. **分类风险**：企业可能同时具有周期、重资产和高增长特征，不能强制单标签。
3. **数据覆盖风险**：详细报表存在公司和年度差异，必须先完成全市场覆盖率诊断。
4. **营运资本口径风险**：直接使用流动资产减流动负债会混入现金和有息债务，应按经营项目构造。
5. **资本开支风险**：现有字段不能稳定区分维持性与扩张性资本开支，重资产企业必须提示。
6. **金融企业风险**：银行、保险和证券公司的普通现金流口径不具有可比性，需独立模型。
7. **结论漂移风险**：UI、AI 和筛选器如果各自计算会产生不一致，必须共享计算层。
8. **业务资料时效风险**：公司简介可能包含历史或宣传性表述，必须展示来源并与最新财报经营变化区分。

## 20. 待用户评估的决策

实施前需要确认：

1. 是否按阶段 A、B、C、D 逐步实施，还是只选择其中部分。
2. 是否接受三情景的初始参数：增长率 `±3` 个百分点、WACC `+1.5/−1` 个百分点、永续增长率 `±0.5` 个百分点。
3. 普通企业首期是否继续使用最近三年平均值作为正常化 FCFF，周期企业改用五年平均值。
4. 是否允许用户手动修正普通企业的估值特征标签。
5. 金融企业第一期只展示关注指标提示，还是同步立项接入专用数据。
6. 顶部总体结论是否使用“低于/位于/高于模型估值区间”这组三态文案。
7. 是否在 FCFF 完成后新增独立的 P/FCF 历史与行业分位。
8. 公司业务简介是否按建议放在基本面内容顶部，位于筛选结论和估值区域之前。
9. 是否展示折叠的“工商经营范围”，还是首期只显示主营业务和公司简介。

在这些决策得到确认前，本方案不进入功能实现。
